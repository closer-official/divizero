# ClaudeCode_OS1修正指示書
# OS① スクリーニング 3ファイル修正

## 背景・目的

OS①の責任範囲を「対象選別 + 属性把握 + 事前仮説構築」に限定する。
S1初回接触文の生成はOS①の出力に残すが、S2以降のラダー記述・DM案生成はOS②が担当する設計に統一する。

**根拠となる設計判断：**
- OS②は「赤信号がなければ前進」の思想で動いており、DM移行はゴールではなく条件が揃った結果
- OS①がS3〜S5のラダーを提示するとユーザーが「次はDMしなければ」と感じる誤った動線になる
- 初回DM案はOS②（dmPrompt.ts）が管理しており、OS①が別途生成すると「公式DM案」が二重になる

---

## Tier1：X版修正（最優先）

### 削除するブロック

**① 進行ラダーブロック全体を削除**

下記のブロック（区切り線ごと）を丸ごと削除する：

```
━━━━━━━━━━━━━━━━━━
【X版 進行ラダー】※接触文はこの順序を前提に生成する

S0：フォロー＋直近ツイートに「いいね」2〜3件（接触当日。リプより先にDMしない）
S1：リプライ（公開返信）。Xの中心的交流。FF外（フォロー外）からのリプは文化的に許容されている。鮮度の高いツイートに返すこと。
S2：リプ往復／会話の成立。相手からのいいね・リプ返し・引用での反応を観測。
S3：DM移行。※Xの最大の関門。DM受信設定が「限定」の相手にはいきなりDMできない。
　・DM開放の相手 → リプ往復が温まったらDMへ。
　・DM限定の相手 → 相互フォロー成立を先に作る（リプ交流で相手からフォローを得る）。相互になればDM可。
　・いきなりのフォロー外DMはリクエスト落ち or 受信拒否で開封されない。S1〜S2を飛ばすことを禁止する。
S4：事業開示
S5：ヒアリング → 軽提案

※引用RT（引用リツイート）での初回接触は禁止。本人と全フォロワーに晒される形になり、業者の宣伝行為に見える。接触はリプかDMで行う。
※FT案件（課題ツイートあり）はS0実施後、その課題ツイートへのリプから即入りしてよい（鮮度が命なので即日）。DM限定の相手でも、まずは課題ツイートへのリプで存在を認知させる。
━━━━━━━━━━━━━━━━━━
```

削除後、「【接触文 生成ルール（全項目必須）】」が直前のブロックに続く形になる。

**② 初回DM生成ルールの削除**

【接触文 生成ルール】内の下記1行を削除する：

```
・初回DM（FT直行かつDM開放の場合のみ）：100〜140文字。課題ツイートへの言及＋自分要素。売り込み・提案・課題指摘は禁止。短く、TLでの会話の延長の温度で。
```

**③ 初回DM案出力ブロックの削除**

【初回接触案】内の下記ブロックを丸ごと削除する：

```
▼初回DM案（FT判定かつDM開放の場合のみ生成。DM限定の相手の場合は「DM限定のためS1リプ→相互フォロー成立まではDM不可」と出力）
案A：
案B：
```

### 追加・変更しない箇所（確認）

- 【UTAGEユーザー確認】ブロック → そのまま残す
- 【外部導線の確認】内のDM開放に関する注記（L46）→ 情報収集の注記として残す
- 【案件ログ転記用】の全項目 → そのまま残す
- S1リプライ案（▼リプライ案）→ そのまま残す

## Tier2：Instagram版修正

### 削除するブロック

**① 進行ラダーブロック全体を削除**

下記のブロック（区切り線ごと）を丸ごと削除する：

```
━━━━━━━━━━━━━━━━━━
【Instagram版 進行ラダー】※接触文はこの順序を前提に生成する

S0：フォロー＋直近投稿に「いいね」2〜3件（接触当日〜前日。コメントより先にDMしない）
S1：投稿コメント（フィード投稿 or リール）またはストーリーへのリアクション
S1-L：ストーリー返信（ここが最強のDM導線。返信はそのままDM受信箱に届く。「DMしていいですか」という関門が存在しない）
S2以降のDM会話：DM文生成OSが担当。このOSはS0〜S1-Lまでの接触文のみ生成する。

※フォロー外からのいきなりDMは「リクエスト」フォルダに落ちて開封されない。S0を飛ばすことを禁止する。
※FT案件（課題発信あり）はS0実施後、その課題投稿へのコメント or ストーリー返信から即入りしてよい（24時間以内）。FT案件でも初回DMはこのOSの責任外。S1-L経由でDM受信箱に届いた後にDM文生成OSへ渡す。
━━━━━━━━━━━━━━━━━━
```

削除後、「【接触文 生成ルール（全項目必須）】」が続く形になる。

### 追加するブロック

**【UTAGEユーザー確認】セクションを新設する**

挿入位置：【事前仮説】ブロックの直後・区切り線の後

以下をそのまま挿入する：

```
━━━━━━━━━━━━━━━━━━
【UTAGEユーザー確認】※UTトラック（UT）の判定に使用
① UTAGEユーザーか：YES / NO
　（根拠：utage-system.comドメイン / 「UTAGE使ってます」系の発信で判定）
② こちらへの認知シグナルあり（いいね・コメント・フォロー等）：YES / NO
　（内容：具体的に記載）
→ ①②ともYES かつ 除外フィルター非該当 → UTトラック確定。FT・NTより優先。ただしDM直行はせず、S0→S1コメントで認知を取ってからOS②へ。
→ それ以外 → 次の【優先度判定】でFT/NTを判定する。
━━━━━━━━━━━━━━━━━━
```

**【優先度判定】の選択肢にUTを追加**

現状：
```
【優先度判定】
優先（FT）/ 通常（NT）
```

変更後：
```
【優先度判定】
優先（FT）/ 通常（NT）/ UTAGEユーザー（UT）
─ UT確定の場合：「UT」と出力。FT/NTの基準は適用しない。
```

**【案件ログ転記用】にUT関連項目を追加**

現状の `トラック判定：` 行の後に下記4行を追加する：

```
UTAGEユーザーフラグ：UT該当 / 非該当
活用度判定：使いこなし / 迷い中 / 不明（UTトラックのみ）
利用プラン推定：ライト / スタンダード / 不明（UTトラックのみ）
認知シグナル内容：（UTトラックのみ・具体的に記載）
```

また `トラック判定：` の選択肢を以下に更新する：

```
トラック判定：SKIP / FT / NT / UT
```

## Tier3：Threads版修正

### 削除するブロック

**① 進行ラダーブロック全体を削除**

下記のブロック（区切り線ごと）を丸ごと削除する：

```
━━━━━━━━━━━━━━━━━━
【Threads版 進行ラダー】※接触文はこの順序を前提に生成する

S0：フォロー＋直近投稿に「いいね」2〜3件（接触当日〜前日。返信より先にDMしない）
S1：公開返信（リプライ）。Threadsの中心的交流であり、温める唯一の手段（ストーリー導線が無いため）。見知らぬ相手からの返信も比較的歓迎される空気がある。
S2：返信往復／会話の成立。相手からのいいね・返信・深掘りを観測。
S3：DM移行。※Threadsの関門。
　・相手がThreadsで自分をフォロー、またはIGで相互フォロー → DMはメイン受信箱に届く。ここまで来てからDMする。
　・上記でない状態のDM → メッセージリクエスト行き（リンク・画像不可、回数上限、開封されにくい）。原則ここには送らない。
　・狙い：S1〜S2の公開返信で関係を作り相手からフォローを得る／またはIG側で相互フォローを作る。どちらかが成立してからDMへ。
S4：事業開示
S5：ヒアリング → 軽提案

※S0・S1を飛ばしたフォロー外いきなりDMは禁止（リクエスト落ち確定）。
※FT案件（課題発信あり）はS0実施後、その課題投稿への返信から即入りしてよい（24時間以内）。
━━━━━━━━━━━━━━━━━━
```
