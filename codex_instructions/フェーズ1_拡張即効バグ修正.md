# フェーズ1: 拡張の即効バグ修正（A1 / A4 / A7）

> 先に `00_共通ルール.md` を読むこと。このフェーズは **chrome-extension/ のみ** を変更する。Webアプリ（src/）は触らない。

## 修正1（A1・最重要）: Geminiタブ再利用時にプロンプト注入・取込パネルが出ない

### 現象
`background/service_worker.js` の `openOrFocusGemini()` は既存Geminiタブがあると**フォーカスするだけ**。
一方 `content/gemini_filler.js` はページロード時に `main()` を1回実行するだけで、`chrome.storage.onChanged` のリスナーを持たない。
→ Geminiタブを開いたまま2件目の「S1接触」を押すと、`s1_touch_context` がstorageに書かれてもGemini側で何も起きない。Xのボタンは「✓ Gemini起動中」のまま。Tab2の「コピーしてGeminiを開く」の `os2_gemini_prompt` も同様の構造問題を持つ。

### 変更内容 — `content/gemini_filler.js`

1. ファイル末尾に `chrome.storage.onChanged` リスナーを追加する:

```js
chrome.storage.onChanged.addListener((changes, area) => {
  if (area !== 'local') return
  // S1コンテキストが新規セットされた（削除・取込済み更新は無視）
  if (changes[S1_TOUCH_KEY]?.newValue && changes[S1_TOUCH_KEY].newValue.promptText
      && !changes[S1_TOUCH_KEY].newValue.capturedRaw) {
    handleS1ContextChange(changes[S1_TOUCH_KEY].newValue)
  }
  if (changes[STORAGE_KEY]?.newValue && changes[STORAGE_KEY].newValue.text) {
    tryFill()
  }
})
```

2. 二重実行ガードを入れる。モジュールスコープに `let lastHandledS1SetAt = 0` を持ち、
   `tryFillS1()` の処理開始時に `ctx.setAt === lastHandledS1SetAt` なら何もしない、処理したら更新する。
   `handleS1ContextChange` は実体としては `tryFillS1()` を呼ぶだけでよい（`tryFillS1` が自分でstorageを読むため）。
   ロード時の `main()` 経由と `onChanged` 経由が同じガードを通るようにすること。

3. 注意点:
   - `s1_touch_context` は background が `capturedRaw` を追記して**同キーを更新する**（`handleS1GeminiCaptured`）。この更新で再度パネルを出さないこと（上記 `capturedRaw` チェックがその目的）。
   - `handleS1TouchSent` / キャンセル時の `remove` では `newValue` が無いので発火しない（`?.newValue` ガードで足りる）。
   - 既にS1取込パネル（`#s1-gemini-panel`）が表示中に新しいコンテキストが来た場合は、古いパネルを消して新しい内容で出し直す（`showS1CapturePanel` は既に既存パネルをremoveしているのでそのままでよい）。
   - `tryFill()`（OS②プロンプト）はstorageから読んで**即キーを削除する**実装なので、複数Geminiタブが開いていても二重挿入はstorage削除の競合で自然に防がれる。変更不要。

## 修正2（A4）: 「OS②選択」のたびにWebアプリのタブが増殖する

### 現象
`background/service_worker.js` の `enqueue` ハンドラが `openOrFocusWebapp()`（既存タブ再利用）を呼ぶ。
それに加えて `content/profile_panel.js` の `os2HandleTweetSelect()` 内、enqueue成功コールバックでも
`window.open(webappUrl)` している（`const openWebapp = (url) => window.open(...)` の一連のブロック）。
→ 押すたびに新規タブが1枚増える。

### 変更内容 — `content/profile_panel.js`

`os2HandleTweetSelect()` の成功コールバックから `openWebapp` 関連のコード（`const openWebapp = ...` から `try { chrome.storage.local.get(['webappUrl'], ...) } catch { openWebapp() }` まで）を**丸ごと削除**する。
タブを開く/フォーカスする責務は background の `openOrFocusWebapp()` に一本化する。
ボタンを「✓ 選択済み」にする処理・`os2-tweet-selected` クラス付与はそのまま残す。

## 修正3（A7）: AI出力・アカウント名の innerHTML 直挿入（XSS・表示崩れ）

### 現象
- `content/s1_touch_scanner.js` の `s1ShowAbPanel()`: `optionA.text` / `optionB.text` / `optionA.judge` / `optionB.judge` / `accountName`（すべてAI出力・外部由来）をテンプレート文字列で `innerHTML` に埋め込んでいる。出力に `</textarea>` 等が含まれるとx.comページ上にHTML注入される。
- `content/gemini_filler.js` の `showS1CapturePanel()`: `ctx.handle` を innerHTML に埋め込んでいる。

### 変更内容

**`s1_touch_scanner.js` — `s1ShowAbPanel()`**:
パネルの**静的な骨組み**（ヘッダー・2つの案ブロック・ヒント行）は innerHTML のままでよいが、動的値の流し込みをすべてDOM APIに変える:

```js
s1FloatingPanel.innerHTML = `...静的テンプレート...`  // ${} を一切含めない
s1FloatingPanel.querySelector('.s1-ab-account').textContent = '@' + (accountName || '')
s1FloatingPanel.querySelector('#s1-judge-a').textContent = optionA.judge || ''
s1FloatingPanel.querySelector('#s1-judge-b').textContent = optionB.judge || ''
s1FloatingPanel.querySelector('#s1-text-a').value = optionA.text
s1FloatingPanel.querySelector('#s1-text-b').value = optionB.text
```

静的テンプレート側は `<span class="s1-ab-judge" id="s1-judge-a"></span>`、`<textarea class="s1-ab-text" id="s1-text-a" rows="3"></textarea>` のように空にしておく。既存のイベントリスナー（閉じる・Aで返信・Bで返信）の挙動は変えない。

**`gemini_filler.js` — `showS1CapturePanel()`**:
ヘッダー行 `💬 S1接触 — @${ctx.handle || ''}` の `${ctx.handle}` を除去し、静的テンプレート＋
`panel.querySelector('#s1-panel-handle').textContent = '@' + (ctx.handle || '')` 方式に変える
（handleの `@` 重複に注意: `ctx.handle` は `@` 付きで保存されている。`'@' + h` ではなく `h.startsWith('@') ? h : '@' + h` とする。s1_touch_scanner側の `accountName` は表示名なのでそのまま `@` 前置でよい—既存表示と同一にすること）。

## 仕上げ

## 受け入れ基準（すべて手動確認）

1. **Geminiタブを開いたままの状態で** x.com のS1接触ボタンを押す → そのGeminiタブにプロンプトが自動挿入され、右下に取込パネルが出る（リロード不要）
2. 連続で別ツイートのS1接触を押しても、都度パネルが新しい対象で出直す
3. Tab2 の「コピーしてGeminiを開く」→ 新タブに挿入される（従来動作の非破壊確認）
4. Webアプリのタブが既に開いている状態でプロフィール画面の「OS②選択」を押す → 既存タブがフォーカスされ、**新規タブは開かない**
5. `===TOUCH_START===` ブロック内に `</textarea><img src=x onerror=alert(1)>` を含むダミー出力を取込 → alertが**発火せず**、文字列としてtextareaに表示される
6. 既存機能の回帰なし: OS⓪ボタン、A/B返信挿入、RECORD_TOUCH記録
