# フェーズ5: 送信検知後のTouch記録・コンテキスト上書き防止（A5 / A6）

> 先に `00_共通ルール.md` を読むこと。前提: フェーズ1〜4適用済み。
> 対象: `chrome-extension/content/s1_touch_scanner.js` / `chrome-extension/background/service_worker.js`

## 背景（現状のデータ整合性欠陥）

### A5: 未送信でもTouchが記録される
`s1_touch_scanner.js` の `s1SendReply()` は、返信欄にテキストを挿入した**直後に** `chrome.runtime.sendMessage({type:'s1_touch_sent', ...})` を送る。backgroundはこれを受けて `RECORD_TOUCH` を実行し、Touch（`status:'awaiting_reaction'`・`repCount+1`・`lastContactDate` 更新）が確定する。
→ ユーザーが結局送信をやめた場合でも記録が残り、48h無反応チェックや接触回数集計が汚染される。

### A6: S1接触コンテキストが黙って上書きされる
`s1_touch_context` は単一キー。取込前に別ツイートでS1接触を押すと前のコンテキストが無警告で消える。ユーザーは前の作業が消えたことに気づけない。

## 変更1（A5）: X側の実送信を検知してから記録する — `s1_touch_scanner.js`

### 1-a. `s1SendReply()` の記録タイミング変更

現在の「挿入 → 即 `s1_touch_sent`」を「挿入 → 送信検知を待つ → `s1_touch_sent`」に変える。

```js
// 返信ダイアログの送信ボタン押下を1回だけ監視する
function s1WatchForSend(sentText, aiSuggestedText) {
  let done = false
  const finish = (recorded) => {
    if (done) return
    done = true
    document.removeEventListener('click', onClick, true)
    clearTimeout(expireTimer)
    s1RemovePendingBar()
    if (recorded) {
      chrome.runtime.sendMessage({ type: 's1_touch_sent', sentText, aiSuggestedText })
      s1Toast('送信を検知しました。タッチを記録します。', false)
    }
  }
  const onClick = (e) => {
    const btn = e.target?.closest?.('[data-testid="tweetButton"], [data-testid="tweetButtonInline"]')
    if (btn) setTimeout(() => finish(true), 800)   // Xの送信処理を待ってから記録
  }
  document.addEventListener('click', onClick, true)   // captureで確実に拾う
  // 10分でタイムアウト → 記録せずコンテキスト破棄
  const expireTimer = setTimeout(() => {
    finish(false)
    chrome.runtime.sendMessage({ type: 's1_touch_cancelled' }).catch(() => {})
    s1Toast('送信が確認できなかったため記録をスキップしました。', true)
  }, 10 * 60 * 1000)
  s1ShowPendingBar(() => finish(true))   // 手動フォールバック
}
```

### 1-b. 手動フォールバックバー

送信検知はDOM依存で壊れうるため、保険UIを付ける:
- `s1ShowPendingBar(onManualRecord)`: 画面下部に固定バー「✍ 返信を送信したら → [送信済みとして記録する] / [記録しない]」を表示（`position:fixed; bottom:0`、既存トーストと同系の見た目、id=`s1-pending-bar`）
- [送信済みとして記録する] → `finish(true)` 相当
- [記録しない] → `finish(false)` ＋ `s1_touch_cancelled` 送信
- 送信ボタン押下を自動検知したときはバーを自動で消す（`s1RemovePendingBar()`）
- バーの文言・ボタンはフェーズ1の規約どおり `textContent` / `createElement` で生成

### 1-c. `s1SendReply()` の変更点まとめ

- 返信欄への挿入成功・クリップボードフォールバックのどちらでも、最後に `s1WatchForSend(sentText, aiText)` を呼ぶ
- 既存の `chrome.runtime.sendMessage({type:'s1_touch_sent',...})` の直接呼び出しは削除
- `s1HidePanel()`（A/Bパネルを閉じる）は従来どおり挿入直後に行う

## 変更2（A6）: コンテキスト上書きの確認 — `service_worker.js` + `s1_touch_scanner.js`

### 2-a. background側 — `handleS1TouchStart()`

冒頭（webappタブ取得の前）に追加:

```js
// 未完了コンテキストの上書き確認（force指定時はスキップ）
if (!params.force) {
  const stored = await chrome.storage.local.get([S1_TOUCH_KEY])
  const prev = stored[S1_TOUCH_KEY]
  if (prev && Date.now() - prev.setAt < 30 * 60 * 1000) {
    sendResponse({ ok: false, code: 'CONTEXT_EXISTS', prevHandle: prev.handle })
    return
  }
}
```

`s1_touch_start` メッセージの `force` フラグを `handleS1TouchStart` に引き渡すこと。

### 2-b. X側 — S1ボタンのクリックハンドラ（`s1InjectButtons` 内）

レスポンスが `code === 'CONTEXT_EXISTS'` の場合:

```js
const ok = window.confirm(`前回の ${resp.prevHandle} への接触が未完了です。破棄してこのツイートで続行しますか？`)
if (ok) {
  chrome.runtime.sendMessage(
    { type: 's1_touch_start', handle: '@' + authorHandle, tweetUrl, tweetText, force: true },
    /* 同じ成功/失敗コールバック */
  )
} else {
  // ボタンを元に戻す（既存のエラー時リセットと同じ処理）
}
```

コールバックの成功/失敗処理は既存と共通化し、コピペ二重化しないこと（クリックハンドラ内にローカル関数 `sendStart(force)` を作って再利用する形を推奨）。

## 仕上げ

## 受け入れ基準

1. A/Bパネルで「Aで返信」→ 返信欄に挿入される → **この時点ではWebアプリにTouchが記録されていない**（Tab2で確認）
2. Xの送信（返信）ボタンを押す → 約1秒後にトースト「送信を検知しました」→ Tab2の該当案件にTouchが記録される
3. 挿入後に返信ダイアログを閉じて送信しない → 下部バーで「記録しない」を選ぶ → Touchは記録されず、コンテキストも消える
4. 挿入後10分放置 → 自動でスキップされ、記録されない
5. 送信検知が効かない環境を想定し、下部バーの「送信済みとして記録する」でも記録できる
6. S1接触の取込前に別ツイートのS1接触を押す → confirmダイアログが出る。キャンセルで前のコンテキストが保持され（Geminiパネルが引き続き有効）、OKで新しい対象に切り替わる
7. 30分以上前の古いコンテキストが残っている場合は確認なしで上書きされる
