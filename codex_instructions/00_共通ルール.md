# Codex実装指示書 — 共通ルール（全フェーズ必読）

この指示書群は `chrome-extension/` とWebアプリの連携改善を6フェーズに分けたもの。
**各フェーズは独立して実装・検証・コミットする。前フェーズの完了を前提に次を実施する。**

## 対象リポジトリ構成（関係分のみ）

```
chrome-extension/            # 現行のChrome拡張（Manifest V3・生JS・ビルド不要）
  manifest.json
  background/service_worker.js
  content/
    twitter_scraper.js       # x.com: OS⓪候補収集ボタン
    profile_panel.js         # x.com: プロフィール画面の「OS②選択」ボタン
    s1_touch_scanner.js      # x.com: 全ツイートへの「S1接触」ボタン・A/Bパネル
    gemini_filler.js         # gemini.google.com: プロンプト自動挿入・取込パネル
    webapp_bridge.js         # Webアプリタブ: background⇔window.postMessage 中継
    id_shim.js               # Webアプリタブ: 拡張IDをDOM属性に書く
    twitter.css
  popup/popup.html, popup.js
salesos-extension/           # 旧拡張（フェーズ6でアーカイブ。それまで触らない）
src/
  App.tsx                    # ルート。registerExtensionBridge の呼び出し元
  services/extensionBridge.ts  # window.postMessage ベースのブリッジ（Webアプリ側受け口）
  services/receive/ReceiveService.ts, useReceive.ts, types.ts  # externally_connectable 経由の受信
  components/tabs/Tab2.tsx   # パイプライン管理（CaseCard内に拡張連携あり）
  utils/touchPrompt.ts       # buildTouchPromptFromTemplate / parseTouchOutput
  utils/helpers.ts           # normalizeHandle / uid / todayStr など
```

## メッセージ経路（現状仕様・重要）

1. **X → background**: `chrome.runtime.sendMessage({type: 's1_touch_start' | 'enqueue' | ...})`
2. **background → Webアプリ**: `chrome.tabs.sendMessage(tabId, {type:'webapp_bridge', bridgeType, payload})`
   → `webapp_bridge.js` が `window.postMessage({source:'salesos-ext', type: bridgeType, requestId, payload})`
   → `extensionBridge.ts` が処理して `{source:'salesos-app', requestId, ...}` を postMessage で返す
3. **Webアプリ → background**: `chrome.runtime.sendMessage(extId, {type:'get_queue' | 'set_gemini_prompt' | ...})`（`onMessageExternal`）
4. **background → Gemini**: `chrome.storage.local` にコンテキストを書き、`gemini_filler.js` が読む

ストレージキー:
- `os_ext_queue` — OS②選択キュー
- `s1_touch_context` — S1接触の進行中コンテキスト（単一）
- `os2_gemini_prompt` — Tab2「コピーしてGeminiを開く」用プロンプト
- `os2_pipeline_handles` — パイプライン登録済みハンドルのキャッシュ
- `os0_prompt_cache` — OS⓪プロンプトの24hキャッシュ

## 全フェーズ共通の禁止事項

1. **`public/prompts/` 配下は一切変更しない**（プロンプト仕様は別管理）
2. 指示された範囲外のリファクタリング・整形・リネームをしない
3. `salesos-extension/` はフェーズ6まで触らない
4. Firestoreのデータ構造（`src/types.ts` の既存フィールド）を壊す変更をしない
5. AI APIの直接呼び出しを追加しない（本アプリはAIを呼ばない設計）
6. UI文言は既存に合わせて日本語

## 全フェーズ共通の実装規約

- 拡張のcontent scriptは**同一ページで複数ファイルが同一スコープを共有する**（twitter_scraper / profile_panel / s1_touch_scanner はすべてx.comで動く）。トップレベルの変数・関数名は必ず既存のプレフィックス規約（`s1`〜 / `os2`〜 など）に従い衝突させない
- 拡張は生JS（ES2020）・`'use strict'`。ビルド工程を追加しない
- 拡張を変更したフェーズでは `manifest.json` の `version` をマイナーバンプする（例: 1.6.0 → 1.7.0）
- 動的な文字列（AI出力・アカウント名・ツイート本文など）を `innerHTML` に埋め込まない。`textContent` / `value` / `createElement` を使う
- Webアプリ側（`src/`）を変更したら `npm run build` が通ること（型チェック含む）
- コミットは1フェーズ1コミット。メッセージは各フェーズ指示書の指定に従う
- **デプロイはユーザーが行う**。Webアプリ側を変更したフェーズでは、作業完了報告の末尾に `npm run deploy --m="<コミットメッセージ>"` を出力すること

## 拡張の動作確認方法

1. `chrome://extensions` → デベロッパーモード → `chrome-extension/` フォルダを「パッケージ化されていない拡張機能を読み込む」
2. 変更後は同画面の「更新」ボタン → 対象タブ（x.com / gemini.google.com / Webアプリ）をリロード
3. WebアプリはローカルならVite（`npm run dev` → http://localhost:5173）、本番は https://divizero.vercel.app — 拡張のpopupでURL切替可能
