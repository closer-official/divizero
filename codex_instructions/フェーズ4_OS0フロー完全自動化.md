# フェーズ4: OS⓪フロー完全自動化（B2）

> 先に `00_共通ルール.md` を読むこと。前提: フェーズ1〜3適用済み（特にフェーズ3の取込機構を再利用する）。
> 対象: `chrome-extension/content/twitter_scraper.js` / `chrome-extension/background/service_worker.js` / `chrome-extension/content/gemini_filler.js`
> Webアプリ側の `OS0_IMPORT` / `GET_EXCLUDED` ブリッジ（`src/services/extensionBridge.ts`）は**実装済み**なので変更不要（読むだけ）。

## 背景（現状の無駄）

現在のOS⓪ボタン（`twitter_scraper.js` の `buildAndSendToAI()`）は:
1. 静的プロンプトファイル＋収集アカウントをクリップボードにコピーし、`window.open` でGeminiを開くだけ
2. ユーザーは Geminiに手動貼り付け → 送信 → 出力を手動コピー → Tab0を開く → 貼り付け → 取込ボタン、と**手動6ステップ**
3. さらに**除外済みリストがプロンプトに入らない**。Tab0の手動コピー（`Tab0.tsx` の `handleCopy` 相当、L122-138）はFirestoreの `data.excluded` から除外リストを動的付加するが、拡張経由は静的ファイルのみ → 除外済みアカウントを毎回AIが再判定する無駄と、二重登録防止がインポート時のdedup頼みになる不整合

これをS1接触と同じ「storage経由自動挿入 → 取込パネル → ブリッジで自動登録」パターンに統一する。

## 設計

新ストレージキー: `os0_context`
```js
{
  promptText: string,        // 完成プロンプト（除外リスト込み）
  channel: 'twitter',
  accountCount: number,
  sourceContext: { platform:'twitter', pageType, url, collectedBy:'chrome-extension', collectedAt },
  xTabId: number,            // 元のXタブ
  setAt: number,
}
```

フロー: Xボタン → `os0_start` メッセージ → background がプロンプト組立（除外リスト取得含む）→ `os0_context` 保存 → Gemini起動 → gemini_filler が自動挿入＋OS⓪取込パネル表示 → 取込（手動 or 自動）→ background が `OS0_IMPORT` ブリッジ呼び出し → 結果をGeminiタブにバナー表示。

## 変更1: `twitter_scraper.js`

`buildAndSendToAI()` を全面書き換え:

1. プロンプト組立ロジック（`fetchOS0Prompt` / `formatAccountsSection` / `buildFullPrompt`）は**そのまま流用**する。
2. クリップボードコピーと `window.open(aiUrl)` を廃止し、backgroundへ送る:

```js
const accountsSection = formatAccountsSection(cards, pageType, location.href)
chrome.runtime.sendMessage({
  type: 'os0_start',
  accountsSection,
  accountCount: cards.length,
  sourceContext: {
    platform: 'twitter', pageType, url: location.href,
    collectedBy: 'chrome-extension', collectedAt: new Date().toISOString(),
  },
}, (resp) => { /* 成功: ボタンを「✓ n件 → Gemini処理中」表示 / 失敗: エラー表示（既存のresetBtnパターン流用） */ })
```

3. プロンプトファイルの取得と除外リスト結合はbackground側へ移す（下記変更2）。content script側の `fetchOS0Prompt` / `buildFullPrompt` はbackgroundへ**移動**する（コピーを残さない）。`formatAccountsSection` はDOM収集と同じ側（content）に残す。
4. `aiTarget` 設定（chatgpt/claude切替）は当面Gemini固定になる旨: `aiTarget` が `gemini` 以外に設定されている場合のみ、従来のクリップボード＋`window.open` 動作にフォールバックする分岐を残す（ChatGPT/Claudeには取込機構がないため）。

## 変更2: `service_worker.js`

`os0_start` ハンドラを追加:

```js
if (message.type === 'os0_start') {
  handleOS0Start(message, sender.tab?.id, sendResponse)
  return true
}
```

`handleOS0Start` の処理:

1. `fetchOS0Prompt(webappBase)`（twitter_scraperから移設。fetch＋24hキャッシュのまま）
2. 除外リスト取得: `findOrOpenWebappTabId()` → `repairWebappBridgeIfNeeded()` → `callWebAppBridge(tabId, 'GET_EXCLUDED', { channel: 'twitter' })` → `payload.handles`（`@xxx` 形式の配列）
   - **Webアプリタブが開けない/応答しない場合は除外リストなしで続行**する（OS0_IMPORT側にdedupがあるため致命的ではない。ただしバナーで「除外リストなしで実行」と表示できるよう、コンテキストに `excludedApplied: boolean` を持たせる）
3. プロンプト結合。`Tab0.tsx` L122-138 と同じ規則に合わせる:
   - ベースプロンプトに `\n\n【除外済みアカウント` セクションが**ある**場合: そのセクションの直前に候補一覧（accountsSection）を挿入し、セクション末尾に除外ハンドルを改行区切りで追記
   - **ない**場合: `プロンプト + 除外セクション + 候補一覧` の順で結合。除外セクションの文言はTab0と同一にする:
     `【除外済みアカウント（再判定不要）】\n以下のアカウントは過去に接触済み・SKIP・除外済みです。▼判定一覧に含まれていた場合は無条件で✕（除外済み）としてください：\n@a\n@b...`
   - ※実装前に `src/components/tabs/Tab0.tsx` の該当ロジックを読んで、順序・文言を正確に一致させること
4. `os0_context` を保存し `openOrFocusGemini()`（フェーズ1のonChangedにより既存タブでも発火する）
5. `sendResponse({ ok: true, accountCount })`

取込受信ハンドラ `os0_gemini_captured` を追加:

```js
if (message.type === 'os0_gemini_captured') {
  handleOS0Captured(message.rawText, sender.tab?.id)
  return false
}
```

`handleOS0Captured(rawText, geminiTabId)`:

1. `os0_context` を読み、無ければ warn して終了
2. `findOrOpenWebappTabId()` → repair → `callWebAppBridge(tabId, 'OS0_IMPORT', { aiOutput: rawText, channel: ctx.channel, sourceContext: ctx.sourceContext })`
3. 結果 `{ ok, passed, ngCount, skippedDuplicates, missing }` をGeminiタブへ送る:
   `chrome.tabs.sendMessage(geminiTabId, { type: 'os0_import_result', result })`
4. 成功時は `os0_context` を削除。失敗時（`ok:false`）は削除せず、Gemini側で再取込できるようにする

## 変更3: `gemini_filler.js`

1. `tryFillOS0()` を追加: `os0_context` があれば（TTL 30分）プロンプトを自動挿入し、OS⓪用取込パネルを表示する。`main()` とフェーズ1の `onChanged` リスナーに組み込む。優先順位は S1 > OS0 > OS2（同時に複数コンテキストが残っていた場合、パネルは1つだけ表示。実運用では同時使用しない想定なので、単純にこの順で早い者勝ちにする）
2. OS⓪用取込パネル（`showOS0CapturePanel`）: S1パネルの構造を流用し、
   - ヘッダー「📥 OS⓪一次選別 — n件」（`accountCount` 表示、フェーズ1同様 textContent で流し込み）
   - `excludedApplied === false` のとき注意書き「⚠ 除外リストなしで実行中（Webアプリ未接続）」を表示
   - 取込処理はフェーズ3の `extractLastModelResponse` を使う。**マーカーはOS⓪出力に固有の見出し**を使う: まず `public/prompts/OS0_X_一次選別_v2.md` の出力仕様を読み、出力に必ず含まれる見出し文字列（例:【判定一覧】等）を確認してマーカー定数 `OS0_OUTPUT_MARKER` に定める。DOMから取れなければクリップボードフォールバック（従来手順の案内文言も残す）
   - 自動取込: OS⓪出力には終端マーカーが保証されないため、**このフェーズでは自動取込は実装しない**（手動「取込」ボタンのみ。ボタン1回で済む）
3. `os0_import_result` 受信ハンドラを追加: バナーで結果表示
   - 成功: `✓ OS⓪取込完了: 通過{passed.length}件 / NG{ngCount}件 / 重複スキップ{skippedDuplicates}件`（緑）
   - 失敗: `⚠ 取込失敗: {missing.join(', ')}。出力形式を確認して再度【取込】を押してください`（赤）
   - `chrome.runtime.onMessage.addListener` はgemini_filler内に既存が無いため新設する

## 仕上げ

- `manifest.json` の `version` を `2.0.0` に上げる。
- Webアプリ側の変更は無いはずだが、`extensionBridge.ts` の `OS0_IMPORT` が `role !== 'admin'` で拒否する点に注意（受け入れ基準7）。

## 受け入れ基準

1. x.com のフォロワー一覧/検索結果でOS⓪ボタン押下 → Geminiが開き（既存タブ再利用含む）、プロンプトが**自動挿入**されている
2. 挿入されたプロンプトに、Firestoreの除外済みアカウント（Tab0の除外リストに表示されるもの）が含まれている
3. Geminiで送信 → 応答完了後に「取込」を1回押すだけで、Tab0を開かずに `screenings` へ登録され、Geminiにバナーで「通過n件/NGn件/重複n件」が表示される
4. Webアプリ側（Tab0）を開くと通過アカウントが一覧に反映されている（Firestoreリアルタイム同期）
5. Webアプリのタブを全部閉じた状態でもフローが完走する（backgroundがタブを自動で開く）
6. 除外リスト取得に失敗した場合でも取込までは完走し、パネルに「除外リストなし」警告が出る
7. viewerロールでログイン中は取込がREADONLYで失敗し、その旨バナー表示される（`OS0_IMPORT` は `{ok:false, code:'READONLY'}` を返す。バナー文言:「⚠ 閲覧モードのため取込できません」）
8. popupで `aiTarget` を chatgpt に変えた場合は従来のクリップボード方式で動く（回帰確認）
