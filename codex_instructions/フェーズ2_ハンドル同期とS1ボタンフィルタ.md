# フェーズ2: パイプラインハンドル同期の復活 → S1ボタン事前フィルタ（A2 / A3）

> 先に `00_共通ルール.md` を読むこと。前提: フェーズ1適用済み。
> 対象: `src/App.tsx` + `chrome-extension/content/s1_touch_scanner.js` + `chrome-extension/content/profile_panel.js`（動作確認のみ）

## 背景（現状の欠陥）

- 拡張の `service_worker.js` は `onMessageExternal` で `set_pipeline_handles` を受け、`chrome.storage.local` の `os2_pipeline_handles` に保存する実装が**既にある**。
- `profile_panel.js` はこのキャッシュを読み「パイプライン案件」バッジを表示する実装が**既にある**。
- しかし **Webアプリ側から `setPipelineHandles()` を呼ぶコードがどこにも存在しない**（`useReceive.ts` に定義だけあり未使用）。→ キャッシュは常に空、バッジは永遠に出ない。
- さらに `s1_touch_scanner.js` は全ツイートにS1接触ボタンを出し、パイプライン未登録アカウントでも押せてしまい、押してから「未登録です」エラーになる（Webアプリタブへの無駄な往復つき）。

## 変更1: Webアプリからハンドル一覧を拡張へ同期する — `src/App.tsx`

`App.tsx` に以下のuseEffectを追加する（既存の `registerExtensionBridge` のeffectの近くに置く）:

```tsx
import { ReceiveService } from './services/receive/ReceiveService'
import { normalizeHandle } from './utils/helpers'   // 既存importに追加

// パイプライン登録済みハンドルを拡張へ同期（S1ボタンの事前フィルタ・プロフィールバッジ用）
useEffect(() => {
  if (loading || checking) return
  const service = new ReceiveService()
  if (!service.isAvailable()) return
  const handles = [...new Set(
    (data.pipeline || [])
      .filter(p => p.isOpen !== false)
      .map(p => normalizeHandle(p.url))
      .filter(Boolean),
  )]
  const timer = setTimeout(() => {
    service.setPipelineHandles(handles).catch(() => {})
  }, 1500)   // 連続保存のデバウンス
  return () => clearTimeout(timer)
}, [loading, checking, data.pipeline])
```

実装上の注意:
- `normalizeHandle` は `src/utils/helpers.ts` の既存関数を使う。**実装を必ず確認し**、`https://x.com/xxx` 形式のURL・`@xxx`・素のハンドルのいずれからも「@なし・小文字」のハンドルを返すことを確認する。もしURL形式を処理できない場合は、`extensionBridge.ts` にある `extractHandleOnly()` をexportして流用する（重複実装を新設しない）。
- 拡張側 `profile_panel.js` の照合は `handles.includes(handle.toLowerCase())`（@なし小文字）なので、**送る形式は「@なし・小文字」に統一**する。
- `service.isAvailable()` がfalse（拡張未インストール）のときは何もしない。エラーをconsoleに出さない。

## 変更2: S1接触ボタンの事前フィルタ — `chrome-extension/content/s1_touch_scanner.js`

1. モジュールスコープにキャッシュを持つ:

```js
const S1_PIPELINE_CACHE_KEY = 'os2_pipeline_handles'   // profile_panel.js と同じキー（constの名前は衝突回避のため別名）
let s1PipelineHandles = null   // null = 未取得（フォールバックで全表示）, Array = 取得済み
```

2. 起動時に読み込み、`chrome.storage.onChanged` で追随する:

```js
function s1LoadPipelineHandles() {
  try {
    chrome.storage.local.get([S1_PIPELINE_CACHE_KEY], (r) => {
      const entry = r?.[S1_PIPELINE_CACHE_KEY]
      s1PipelineHandles = Array.isArray(entry?.handles) ? entry.handles : null
      // フィルタ条件が変わったので注入済みフラグをリセットして再スキャン
      document.querySelectorAll('article[data-s1-injected]').forEach(el => { delete el.dataset.s1Injected })
      s1ScheduleScan()
    })
  } catch (_) {}
}
chrome.storage.onChanged.addListener((changes, area) => {
  if (area !== 'local' || !changes[S1_PIPELINE_CACHE_KEY]) return
  s1LoadPipelineHandles()
})
s1LoadPipelineHandles()
```

3. `s1InjectButtons()` のループ内、`authorHandle` 取得後に判定を追加:

```js
// パイプラインハンドルのキャッシュがある場合のみフィルタ（未取得なら従来どおり全表示）
if (Array.isArray(s1PipelineHandles) && !s1PipelineHandles.includes(authorHandle)) continue
```

注意:
- `s1GetTweetAuthor()` は既に小文字・@なしを返すので、そのまま `includes` 照合できる。
- **フィルタで弾いた article にも `data-s1-injected` は立てない**こと（後からハンドル一覧が更新されたとき再判定できるように、`continue` は `article.dataset.s1Injected = '1'` の**前**で行う）。
- キャッシュ未取得（拡張だけ入れていてWebアプリを一度も開いていない等）の場合は従来どおり全ツイートに表示し、押下時のエラーで案内する（既存動作をフォールバックとして温存）。

## 仕上げ

- `manifest.json` の `version` を `1.8.0` に上げる。
- `npm run build` が通ることを確認（App.tsx変更のため）。

## 受け入れ基準

1. Webアプリを開くと（拡張インストール済み環境で）1.5秒後に `chrome.storage.local` の `os2_pipeline_handles.handles` にオープン中パイプラインのハンドル（@なし小文字）が入る（service workerのDevToolsで確認）
2. パイプライン登録済みアカウントのプロフィールを開く → 「パイプライン案件」バッジが表示される（既存の死んでいた機能が復活）
3. タイムライン/検索で、**パイプライン登録済みアカウントのツイートにだけ** S1接触ボタンが表示される
4. Webアプリで案件をクローズ → Webアプリタブを表示し直す（データ変更が同期される）→ x.comをリロードすると該当アカウントのボタンが消える
5. 拡張のstorageを手動でクリアした状態（キャッシュなし）では従来どおり全ツイートにボタンが出る
6. `npm run build` 成功
